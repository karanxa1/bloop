how it works

plan → act → verify → attest

bloop never claims what it cannot prove. every run follows the same four steps, and all of it streams live into the chat and the proof trace.

  1. 01

    plan

    thinks out loud, then writes a step plan that updates as it learns. think mode forces the plan first.

    think → tool → think

  2. 02

    act

    calls mcp tools across apps in parallel, with results kept in order, and hands bigger jobs to streamed subagents.

    join_all · delegate

  3. 03

    verify

    every write is followed by an independent read-back before bloop may say "done". unverified writes get flagged in the ui.

    write → read-back → match

  4. 04

    attest

    each verification is appended to a tamper-evident ledger you can audit in the proof trace or at /api/ledger.

    sha256(prev_hash ‖ entry)

  1. entry 1
    #7b2d…04aa

change any entry and every hash after it breaks.

failure protection

  • per-tool timeouts
  • per-server circuit breaker
  • mcp retries, backoff and re-init
  • error kinds + retry counts, shown in the ui
  • bad tool arguments self-corrected
  • model fallback: stream → non-stream → backup model
  • unverified writes flagged
  • errors reported, never papered over
